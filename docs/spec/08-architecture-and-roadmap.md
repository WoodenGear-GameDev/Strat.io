# 08. Техническая архитектура, производительность и план реализации

## 1. Архитектура системы (Workspace и сервисы)
Серверно-авторитарная модель с единым детерминированным ядром на Rust и высокочастотным веб-клиентом:

- **`crates/game-core`** — чистая детерминированная симуляция мира (без сети, ФС, БД, системного времени; компилируется в native и `wasm32-unknown-unknown`). Внутренние подсистемы:
  - `hex` — гексагональная и суб-ромбовая (3 генератора в гексе) сетка, BFS связности по граням и зоны поддержки Узлов;
  - `polar` — 3 концентрических кольца, гравитация массы Ядра, полярная навигация `(r, θ)`;
  - `squads` — производство, лимит контроля, автокластеризация (разделение/слияние), автоподкрепление, патруль, телепорт с зарядкой;
  - `combat` — турели, анти-базовые пушки Рубаки, снаряды, урон, 100% награда за оторванные модули;
  - `pve` — Агрессивные ульи (Ring 1), Курсирующие зоны подавления (Ring 1–2), Точки притяжения (Ring 1–2);
  - `visibility` — серверный туман войны, глушилка Стелсера, тепловая карта «красного тумана»;
  - `bots` — честный ИИ-игрок поверх того же `Command` API (0 преимуществ и 0 скрытых ограничений);
  - `protocol` — компактный бинарный кодек команд и снэпшотов.
- **`crates/game-node`** — WebSocket-узел (`Axum + Tokio`), без прямого доступа к БД (валидация JWT в памяти), подходит для онлайна и LAN. Отправляет итоги матчей в `meta-server`.
- **`crates/meta-server`** — HTTP REST API (`Axum + SQLite/sqlx`): аккаунты, регистрация/вход, JWT, профили, статистика, глобальный лидерборд, список серверов.
- **`crates/game-wasm`** — сборка `game-core` в WebAssembly, запускается строго в **Web Worker** (оффлайн-режим без нагрузки на главный поток рендера).
- **`client/`** — чистый TypeScript + Vite + **WebGL2** рендерер + абстракция `Transport` (`WsTransport` / `WorkerTransport`).
- **`config/balance.json`** — единый декларативный источник параметров баланса для ядра и клиента.

## 2. Целевая производительность: 120+ FPS
Бюджет кадра на 120Hz экранах (ПК и смартфоны) — **<= 8.33 мс**. Архитектурные требования клиента:
- **Оптимизированный Canvas2D (`alpha: false`, DPR cap 1.5):** процедурная геометрия в стиле старого Stratio (Material 3 Expressive) с culling вне экрана.
- **Быстрый туман войны:** offscreen `fogCanvas` в `0.25x` разрешении (в 16 раз меньше пикселей) — мягкий край и `< 0.2 мс` на кадр.
- **Zero-GC в render-loop:** предвыделенные `Float32Array` буферы, объектные пулы, отсутствие аллокаций внутри `requestAnimationFrame`.
- **Изоляция потоков:** в оффлайне симуляция (`game-wasm`) работает в Web Worker, не вызывая микрофризов в главном потоке.
- **Лёгкий HUD:** DOM-элементы обновляются только при изменении значений (без layout thrashing и перерисовки DOM каждый кадр).
- **Интерполяция:** симуляция на `20–30 TPS` (фиксированный шаг `dt`) + субкадровая интерполяция по `performance.now()` на родной частоте экрана (120 / 144 / 240 Hz).

## 3. Сетевой протокол и серверный туман войны (Anti-MapHack)
- **Персонализированный снэпшот:** для каждого игрока сервер фильтрует мир по его текущей видимости (с учётом глушилки Стелсера) — скрытые вражеские базы, модули и дроны **не передаются** по сети.
- **Глобальный слой миникарты:** передаётся всем игрокам — световые сигналы Точек притяжения, Зоны подавления с векторами, очаги «красного тумана» и лидерборд.
- **Версионирование геометрии баз:** структура модулей базы пересылается при изменении (стройка/апгрейд/разрушение), а каждый тик обновляются только динамические поля (позиция, HP, углы, снаряды, дроны).

## 4. План реализации (Roadmap)
1. **Фаза 1 — Ядро, WebGL2 120+ FPS и живой оффлайн-полигон:**
   - Каркас Rust workspace (`game-core`, `game-wasm`) + `config/balance.json`;
   - Базовые механики в `game-core`: гекс+ромб сетка, связность и отрыв, 3 кольца и гравитация массы, экономика (Энергия, Эссенция в Ядре, Реген базы), фабрики/дроны/отряды/автоподкрепление, телепорт, туман войны;
   - Минимальный PvE-полигон в Ring 1 (Агрессивные ульи на той же гекс-сетке + Точки притяжения), чтобы сразу можно было полноценно щупать всю кор-петлю развития и перехода во 2-е кольцо;
   - WebGL2-клиент (`120+ FPS` + Web Worker транспорт), «замирающая» камера, управление ПК + смартфон.
2. **Фаза 2 — Модификаторы, полный PvE и Боты:**
   - Все 4 модификатора (Кукловод, Стелсер, Рубака, СДВГшник);
   - Курсирующие зоны подавления (Ring 1–2), полный PvE-баланс и «красный туман» на миникарте;
   - Полноценные честные ИИ-боты.
3. **Фаза 3 — Онлайн, LAN и Мета-сервер:**
   - `game-node` (WebSocket, серверный туман войны, LAN-режим);
   - `meta-server` (SQLite, аккаунты, JWT, профили, глобальный лидерборд).
4. **Фаза 4 — Баланс, полировка и нативные обёртки:**
   - Итеративный баланс `balance.json` (включая доработку ролей Кукловода — Танки/Рейдеры и архетипов ботов);
   - Полировка мобильного UX, деплой и нативные обёртки (`src-tauri` / mobile).

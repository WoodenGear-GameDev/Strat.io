# 09. Детальная архитектура, поток данных и стандарты кода

## 1. Инженерные стандарты (защита от спагетти)
1. **Один источник правды:**
   - вся игровая логика — исключительно в `crates/game-core`;
   - все числовые параметры — исключительно в `config/balance.json` (типизированный `BalanceConfig` с валидацией при старте);
   - клиент — тонкий высокочастотный рендер + ввод без дублирования игровой логики.
2. **Малые модули и одна ответственность:**
   - целевой размер файла — **150–350 строк**; крупные домены дробятся на чистые подмодули;
   - `world.rs` хранит только данные и базовые операции доступа — бизнес-логика живёт в `systems/*`.
3. **Строго однонаправленные зависимости (DAG):**
   - `types` / `config` / `hex` — чистые структуры и функции, не знающие о `World`;
   - системы в `systems/*` не вызывают друг друга напрямую — взаимодействие идёт через состояние `World` и явный буфер событий тика (`TickEvents`);
   - на клиенте: `transport` → `state` → (`render`, `ui`); `input` → `transport` (UI и рендер изолированы).
4. **Без автотестов:** юнит-тесты и тестовый код не пишутся; проверка выполняется компиляцией (`cargo check` / `npm run build`), ревью и живым запуском.
5. **Пошаговая инкрементальная сборка:**
   - разработка ведётся малыми прозрачными шагами с проверкой и документацией (`README.md`) на каждом модуле.

```text

├── config/

├── docs/spec/                      # Спецификация проекта (01..09)
│
├── crates/
│   ├── game-core/                  # Чистая детерминированная симуляция
│   │   └── src/

│   │       ├── config.rs           # BalanceConfig + строгая валидация
│   │       ├── types.rs            # ID-типы, Vec2, Polar, перечисления модулей и модификаторов
│   │       ├── hex.rs              # Гекс-сетка + 3 ромба-генератора, смежность граней, BFS
│   │       ├── spatial.rs          # SpatialGrid для O(1) запросов радиусов и коллизий
│   │       ├── events.rs           # Буфер событий тика (TickEvents)
│   │       ├── world.rs            # Хранилище сущностей (только данные)
│   │       ├── commands.rs         # Валидация и применение команд игроков/ботов
│   │       ├── systems/            # Упорядоченные фазы одного тика:
│   │       │   ├── economy.rs      # Генераторы, зоны подавления, глушилка, реген базы
│   │       │   ├── physics.rs      # Кольца, гравитация массы, омни-дрейф, коллизии баз
│   │       │   ├── production.rs   # Фабрики, лимит контроля, снос сверхлимитных дронов
│   │       │   ├── squads.rs       # Полярная навигация, кластеризация, автоподкрепление, патруль
│   │       │   ├── teleport.rs     # Зарядка, сбор патруля, перенос базы
│   │       │   ├── combat.rs       # Стрельба, урон, отрыв веток (100% награда), захват Ядра
│   │       │   ├── pve.rs          # Ульи (Ring 1), Зоны подавления, Точки притяжения
│   │       │   └── visibility.rs   # Туман войны, Стелсер, «красный туман»
│   │       ├── bots/               # Честный ИИ (читает только свой visibility-срез, шлёт Command)
│   │       └── protocol/           # Бинарный кодек (единый для WS и WASM)
│   │
│   ├── game-wasm/                  # WebAssembly-обёртка для браузерного Web Worker (Offline)
│   ├── game-node/                  # Онлайн / LAN WebSocket сервер (Axum + Tokio, без БД)
│   └── meta-server/                # Аккаунты, JWT, профили, лидерборды (Axum + SQLite/sqlx)
│
└── client/                         # Веб-клиент (TypeScript + Vite + WebGL2 120+ FPS)
    └── src/
        ├── main.ts                 # Точка входа и маршрутизация экранов
        ├── config.ts               # Типы BalanceConfig (получается из Welcome)
        ├── transport/              # Абстракция Transport: WsTransport / WorkerTransport
        ├── state/                  # Бинарный декодер (без GC) + интерполятор 120+ FPS
        ├── render/                 # WebGL2: SDF-шейдеры, Float32Array батчер, туман войны, камера
        ├── input/                  # Машина состояний ввода + адаптеры desktop / touch
        └── ui/                     # Лёгкий HTML-HUD (dirty-check), миникарта, меню, лобби
```

## 3. Конвейер одного тика (`World::step(dt)`)
Строго детерминированный порядок фаз без скрытых побочных эффектов:

1. **`commands`** — валидация и применение накопленных команд игроков и ботов.
2. **`spatial`** — перестроение `SpatialGrid` по актуальным координатам сущностей.
3. **`pve`** — движение Зон подавления, спавн/регенерация Ульев и Точек притяжения.
4. **`economy`** — выработка генераторов (с учётом зон подавления), расход глушилки Стелсера, плавный «Реген базы».
5. **`physics` & `teleport`** — гравитация массы Ядра, омни-дрейф СДВГшника, коллизии баз, зарядка и завершение телепортов.
6. **`production` & `squads`** — выпуск дронов, списание сверхлимитных, полярное движение по дуге, автокластеризация отрядов, патруль и автоподкрепление.
7. **`combat` & `hex`** — стрельба турелей/Рубаки/дронов, урон, BFS связности + проверка зон Узлов, мгновенный отрыв с 100% наградой, передача Эссенции при гибели Ядра, запись в «красный туман».
8. **`visibility`** — пересчёт кругов обзора и видимости с учётом Стелсера.
9. **`bots`** — принятие решений ИИ-ботами по их личному visibility-срезу (формирование `Command` на следующий тик).
10. **`protocol`** — сериализация персонального бинарного `Snapshot` для каждого игрока.

## 4. Поток конфигурации и данных
- **Конфиг:** `config/balance.json` читается сервером (`game-node`) с диска или вшивается в `game-wasm` (`include_str!`), валидируется в `BalanceConfig` и отправляется клиенту один раз в пакете `Welcome`.
- **Команды:** `Input` → `Command` (байты) → `Transport` (`WS` или `Worker`) → `game-core::apply_command`.
- **Отрисовка (120+ FPS):** `game-core::snapshot_for(player)` → `Transport` → `Decoder` (запись в предвыделенные `Float32Array`) → `Interpolator` (`requestAnimationFrame`) → `WebGL2 Renderer` + `HUD (dirty-check)`.
